# Roadmap incremental

> **Nota de atualização (17/09/2026):** esta tabela ficou parada em "Planejada" para as fases 9–15 por um longo período, mesmo depois de essas entregas terem sido implementadas. A situação abaixo foi conferida diretamente no código (rotas, controllers, testes, `frontend/public/assets/js/*`) nesta data. Para o estado atual, completo e por assunto, veja [guia-desenvolvedor.md](guia-desenvolvedor.md) (visão técnica), [guia-analista.md](guia-analista.md) (regras de negócio) e [operacoes.md](operacoes.md) (operação/deploy). Este arquivo continua como registro histórico do planejamento original.

Cada fase exige implementação, validação, testes, documentação e OpenAPI dos endpoints entregues. Integração visual é exigida quando aplicável, a partir da Fase 13. Não antecipar toda a aplicação em um único arquivo.

| 11 | Consolidação de toda a documentação Swagger/OpenAPI | **Parcial** — `backend/docs/openapi.json` é gerado por `tools/generate-openapi.mjs` e mantido em sincronia com as rotas por teste automatizado (`ApiInfrastructureTest`); uma UI Swagger é servida em `backend/public/docs/`. Falta consolidar exemplos/schemas nomeados (a maioria dos corpos ainda é inline) e documentar o mobile como consumidor. |
| 12 | Consolidação de testes unitários, integração, segurança e regressão financeira | **Parcial** — backend com ~76 métodos de teste PHPUnit cobrindo autenticação, cadastros, movimentos, faturas, parcelas, recorrências, empréstimos, planejamento, metas, importação e relatórios; mobile com 42 testes Jest (utilitários e serviços). O frontend PHP não tem suíte automatizada — verificação é manual e por revisão adversarial (ver [guia-desenvolvedor.md](guia-desenvolvedor.md)). |
| 13 | Frontend PHP puro, sessão, ApiClient, Tailwind, Chart.js, telas e modais | **Concluída** — todas as 21 páginas de `routes/pages.php` implementadas (dashboard interativo, CRUD genérico, categorias em árvore, orçamento, quinzena, relatórios, importação, configurações), sessão com refresh automático de token, CSRF, gateway `api.php` com allowlist. Ver [frontend/README.md](../frontend/README.md). |
| 14 | Integração ponta a ponta, erros, expiração e responsividade | **Parcial** — tratamento de 401/419/422/503 implementado no gateway e no cliente JS; responsividade básica (menu mobile) presente no layout. Não há suíte de testes end-to-end automatizada (ex.: Cypress/Playwright); a validação até aqui foi manual mais revisão adversarial por agentes. |
| 15 | Homologação com os dados confirmados, roteiro de aceite e instalação | **Pendente** — as decisões financeiras de [decisoes-pendentes.md](decisoes-pendentes.md) (datas do consignado, renda líquida de desconto em folha, datas de crédito quinzenais) continuam em aberto; sem elas, o consignado e as rendas recorrentes seguem em rascunho/inativos por design. |
| 16 *(fora do plano original)* | Aplicativo mobile Android (React Native + Expo/Metro): dashboard interativo, consulta de lançamentos/cartões, captura automática de notificações bancárias com fluxo de lapidação, sincronização online/offline | **Concluída a parte que dá para validar sem Android Studio** — TypeScript, ESLint e 42 testes Jest passam; captura nativa de notificações e build de APK **não foram validados** nesta máquina (sem SDK/emulador Android). Ver [mobile/README.md](../mobile/README.md), seção "O que falta para concluído de ponta a ponta". |

Relatório de cada fase: alterações, arquivos, tabelas, endpoints, validações, testes/resultados, pendências e próxima fase. PDF e evolução patrimonial permanecem futuros, conforme o prompt.

**Lacuna real de processo:** o projeto ainda não é um repositório Git (`git init` nunca foi executado, apesar de `.gitignore` e `.github/workflows/` já existirem) e o workflow de CI/CD existente (`.github/workflows/main.yml`) publica por FTP num caminho de outro projeto (`clickresto-api`) — ver [CONTRIBUTING.md](../CONTRIBUTING.md) para detalhes e o que fazer antes de usar esse workflow.
